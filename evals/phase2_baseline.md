## Observations

- **A real dispatch bug was found and fixed via this eval run, not before it.** The first pass
  of this eval had the retriever's year-scoped dispatch also filter by the plan's `report_ids`
  when both were present. `gq-003`'s planner named `report_ids: ["2023_annual_en"]` for an
  `operating_income` question — the right metric, wrong report (the figure lives in
  `2023_financials_en`) — and that filter combination silently excluded the correct report,
  producing a fully-cited but substantively wrong "no evidence provided" answer that the
  citation-presence check still labeled `ok`. Fixed in `hfx_portgraph/agent.py::build_dispatch_units`
  by dropping `report_ids` as a filter on the year-scoped path entirely (design.md Decision 4 only
  specifies it for the no-year path) — broadening a year-scoped query can only add candidates, never
  wrongly exclude the report that actually has the answer. The table and answers above are from the
  re-run *after* this fix; `gq-003` went from a false "no evidence" to the correct
  `2023_financials_en` citation once corrected (see below).
- **`ok` still only means "a citation tag is present," not "the answer is correct."** Same
  caveat `phase1_baseline.md` raises for `ask()` — this agent reuses the identical
  `"chunk_id=" in answer.lower()` heuristic (design.md Decision 7) for exactly that reason
  (consistency, not because it's a stronger check). All 13 `ok` results above were spot-read for
  substance below; a few items surfaced real, worth-flagging gaps despite the `ok` label:
  - **`gq-022`'s planner missed a requested year.** `expected_evidence.years` is
    `[2021, 2022, 2023]`; the planner's own plan only came back with `[2022, 2023]`. Since the
    critic only checks coverage of years *the plan itself* names, a planner that never asks for
    2021 produces no gap for it — the agent has no way to notice a year it didn't think to plan
    for. This is the residual edge of the `llama3.1` structured-output risk design.md already
    flags, just manifesting as an incomplete plan rather than malformed JSON.
  - **`gq-025` surfaced a real cross-report figure discrepancy, unresolved.** 2020 net earnings
    read $11,132 from `2020_annual_en` in one run of this eval and $9,148 from
    `2020_financials_en::child::00011` in another (same golden question, different dispatch/
    sampling path). The critic's presence-only coverage check (Decision 5) has no way to catch
    this — both hits are real, cited, and "cover" the 2020 slot; only a semantic-correctness
    check (explicitly out of scope, design.md non-goals) would flag the conflict. Worth a
    manual look at whether these are genuinely different line items (e.g. one restated) or a
    retrieval/table-row mixup, before trusting either figure at face value.
  - **`gq-001` showed real run-to-run variance**, expected from an 8B local model's sampling:
    one run (captured above) reported container throughput for 2020/2021 only and explicitly
    flagged 2022/2023 and all-years operating income as "no evidence found"; a separate manual
    run during development of this change (not the run captured in the table, same question, same
    index) produced a materially fuller answer citing operating income for all four years
    ($11,132 → $13,841) and strategic initiatives from three separate report-years. Both runs
    plan the correct year span and both cite real evidence; which subset of retrieved evidence
    the synthesizer foregrounds varies by run. Contrast with Phase 1's `gq-001`, which
    deterministically missed 2023 at the *retrieval* layer every run — Phase 2's variance is at
    the *synthesis* layer, evidence for the missing years is present in accumulated state
    (`scripts/scratch/phase2_agent_eval.json`'s `evidence`) even on the run where the answer
    didn't surface it, which is a narrower and more tractable gap than Phase 1's.
- **`gq-020`'s answer improved materially after the dispatch fix**, independent of gq-003: without
  the wrong report_id filter narrowing what got compared, the model directly quoted the
  comparative-column figures ($15,945 / $16,070) from `2023_financials_en`'s own statement of
  earnings, rather than an earlier run's confused attempt to derive operating income via
  subtraction across a mix of annual and financials sections.
- **Latency**: 8-46s per question locally (GPU-accelerated `llama3.1` via Ollama), most of it in
  the synthesizer call once `_num_ctx_for()` sizes the context window to the assembled evidence
  (`agent.py`) — multi-year plans with more dispatch units and larger synthesis contexts run
  longer, as expected.

## Summary

13/13 items returned `ok` (cited, non-empty) status; per-item substance was manually checked
against expected evidence rather than trusted from the status label alone (see Observations
above for the gaps that check surfaced). Directionally, this is a clear improvement over Phase 1
on the items that were its documented ceiling — `gq-001` now plans and retrieves evidence across
the full 2020–2023 span instead of missing 2023 outright, `gq-003` gets a correct, specifically
cited figure instead of `answer_uncited`, and both `year_collision` items (`gq-019`, `gq-020`)
resolve the native/comparative year split from the correct statement section without the
`phase1_baseline.md`-documented footnote collision. See `scripts/scratch/phase2_agent_eval.json`
for full plans/answers/citations per item, and the per-item table above for a like-for-like
comparison against `evals/phase1_baseline.md`'s table.
